# 人物动作时序一致性

本规范解决“某一帧看起来接触，但连续动画不成立”的问题。静态 Hero Frame 只能证明一个时刻；动作还必须在时间轴上保持身体、接触、对象和结果的连续因果关系。

## 1. 五阶段动作弧

每个含峰峰的动作场必须在 `storyboard.json` 写入 `action_phases`：

1. `anticipation`：预备，视线、重心或手臂先朝目标建立意图；
2. `contact`：建立接触或明确视线锁定；
3. `manipulation`：真正按、推、拉、转、写、搬、走或递接；
4. `release`：离开、回弹、放手或完成承重转移；
5. `result`：对象变化和可验证结果留在画面中。

阶段必须按顺序、时间连续。接触型动作在 `contact` 与 `manipulation` 两阶段都必须标记 `contact:true`，不能只在一帧碰上后马上脱离。

## 2. 运动实现策略

每个峰峰场景必须声明 `motion_strategy`：

- `static-overlay`：单张静态透明图；只允许观察、思考、指向、惊讶、总结等 `gaze-gesture`。
- `anchored-micro-motion`：人物整体做小于约 12px 的同步位移，对象在同一接触锚点压缩/回弹；只允许简单点击、按压等 `surface-contact`。
- `rigged-animation`：手臂、手腕、躯干等分层绑定；适合轨迹清楚且可控的接触动作。
- `pose-sequence`：至少 3 个动作姿势，覆盖接触前、操纵中和结果；适合推拉、搬运、递接等。
- `integrated-frame`：人物和环境作为同一完整画面生成；适合精确抓握、受力、承重和复杂遮挡。
- `generated-video`：连续视频生成；适合行走、跑跳、转身和复杂全身动作。

硬规则：

- 单张 `static-overlay` 禁止承担任何接触动作。
- `anchored-micro-motion` 只适用于按钮按压等简单表面接触，禁止用于转动、推拉、搬运、坐靠、行走、递接。
- `force-contact`、`body-support`、`locomotion`、`handoff`、`environment-integrated` 必须使用 `rigged-animation`、`pose-sequence`、`integrated-frame` 或 `generated-video`。
- `pose-sequence` 至少 3 姿势；旋转、步态、递接等复杂动作通常需要 4–6 姿势。

## 3. 动作族时序门禁

### 看 / 指 / 思考 / 反应

- 视线先锁定目标，再出现手势或表情变化；
- 目标必须可见，人物不能在目标出现前就指向空处；
- 可使用 `static-overlay`，但人物入场、目标强调和结果必须按因果顺序。

### 按 / 点

- 指尖先到按钮顶面；
- 人物与按钮沿同一轴同步下沉；
- 接触期间指尖与按钮的相对位置基本不变；
- 界面、齿轮、灯或结果在按下后响应；
- 释放后按钮回弹，结果保留。

### 滑 / 写 / 画 / 擦

- 指尖或笔尖持续贴住表面；
- 轨迹与新增/消失痕迹同步；
- 手腕、视线和运动方向一致；
- 单张静态人物禁止假装连续书写或滑动。

### 握 / 转

- 手指先包裹握点；
- 手腕、前臂和把手绕同一旋转轴变化；
- 整个操纵阶段接触点不能穿过手掌或离开手指；
- 指针、齿轮或对象角度同步响应；
- 静态手 + 独立旋转把手直接判失败。

### 推 / 拉

- 接触建立后，手、肩、躯干和重心共同响应；
- 人物与对象沿受力方向保持关系；
- 对象位移不能早于身体发力；
- 放手后对象停在新状态，而不是弹回旧位置。

### 拿 / 举 / 搬 / 放

- 抓握后，物件必须从原支撑面脱离；
- 手与物件在搬运段保持固定相对关系；
- 肩、肘和重心体现重量；
- 放置时先接触新支撑面，再松手，归属变化清楚。

### 插 / 拔 / 连接 / 组装

- 接口先对齐，再沿唯一轴移动；
- 接触深度连续变化，不能瞬移；
- 锁定、亮灯或模块归位只能发生在连接完成后。

### 坐 / 靠 / 扶 / 攀爬

- 支撑接触先建立，再转移身体重量；
- 臀、脚、手、背与支撑面持续接触；
- 环境必须对人物形成合理遮挡和承托。

### 走 / 跑 / 跳 / 转身

- 必须有连续步态或姿势序列；
- 脚与地面接触相位、重心和手臂摆动一致；
- 背景位移不能替代人物步态；
- 单张人物平移直接判失败。

### 递 / 接 / 协作

- 递出者先持有；
- 中段双方共同接触并发生承重转移；
- 结束时接收者持有、递出者释放；
- 物件不能在两人之间漂浮或瞬移。

## 4. 采样与QA

每个动作至少检查以下时间点：

- 预备中段；
- 首次接触；
- 操纵 25%、50%、75%；
- 释放；
- 结果完成态。

强交互和行走至少每 0.2–0.4 秒采样一次。把采样帧做成顺序联系表，逐项检查：

- 身体运动是否与动作匹配；
- 接触是否持续；
- 运动轴和受力方向是否一致；
- 是否出现穿手、脱手、漂浮、脚滑或突然换姿势；
- 对象响应是否晚于动作、早于结果；
- 结果是否有可读停留。

单张 Hero Frame 通过而动作序列失败时，以动作序列为准，禁止批量渲染。

## 5. 自动验证

运行：

```bash
python3 scripts/validate_action_timeline.py project/storyboard.json --strict
```

Storyboard Schema 2.1 起，`validate_package.py` 会自动执行同一门禁。该脚本检查策略与动作类型是否匹配、五阶段是否完整连续、接触是否贯穿操纵段，以及姿势序列数量下限。

自动验证不能判断像素级手部质量；仍必须检查动作顺序联系表。

## 6. 无物理接触的语义姿势序列

当强交互素材不可用、生成结果不稳定，或现有人物资产没有可信抓握姿势时，不要把静态人物硬贴到按钮、摇柄或机器旁。可把场景重写为 `gaze-gesture + pose-sequence`：

1. 选择至少3个已验收姿势，分别承担观察/思考、判断/选择、确认/庆祝；
2. 外部物件只在对应姿势已经稳定出现之后响应，例如目标高亮 → 连接建立 → 响应扩散 → 结果通过；
3. `interaction_contract` 明确 `contact_points: []`，不得把节点之间的“连接”描述成人物手部接触；
4. 姿势切换采用同一帧 `set`/硬切，或用完整遮罩桥接；禁止两张人物图交叉淡化造成双人重影，也禁止先淡出后淡入留下空人物帧；
5. 姿势卡保持固定位置、尺寸和裁切，外部节点、连线、字幕与人物互不遮挡；
6. 抽取切换前一帧、切换后一帧和每个物件响应完成态，确认“人物先变化，物件后响应”。

这种方案是可靠的语义联动回退，不等同于物理操作动画。文稿若明确要求抓、按、推、转、搬运或行走，仍必须使用可改变关节的姿势序列、整帧生成、绑定动画或连续视频，不能偷偷改成手势后继续声称发生了物理接触。

## 7. 修复优先级

1. 动作超出素材能力：换 `motion_strategy`，不要移动静态 PNG 掩盖问题；
2. 简单表面接触：把动作重写为按钮按压等单轴动作，并让人物/对象同步微动；
3. 强交互：改用整帧生成、姿势序列、骨骼绑定或连续视频；
4. 强交互资产暂不可用且语义允许：重写为无接触语义姿势序列，明确不再声称物理操作；
5. 接触漂移：统一人物与对象的运动父级或接触锚点；
6. 对象提前响应：重排时间线，确保动作先于响应；
7. 结果太短：延长 `result` 阶段，不要压缩成一闪而过。

# 场景语法

每个场景只有一个视觉任务。先确定 `visual_template`，再设计物件和动作。

## 模板表

### hook

- 时长：3–8 秒。
- 职责：反常识判断、异常现象或强冲突。
- 画面：一个巨大主物件 + 一条短结论；可让峰峰提出疑问、按下按钮或揭开遮罩。
- 动作：scale-in、震动、仪表拉升、遮罩揭示。
- 禁止：背景介绍、三行以上解释。

### metaphor

- 时长：4–8 秒。
- 职责：把抽象概念绑定到日常物件。
- 画面：一组对照物、一台机器或一条路径。
- 动作：输入→转换→输出。
- 禁止：同时使用两个互相竞争的比喻。

### diagram

- 时长：4–10 秒。
- 职责：机制、架构、流程、数据关系。
- 画面：2–5 个节点，一条主路径。
- 动作：节点依次出现、线条生长、状态写入。
- 禁止：所有节点同时静态出现。

### chapter-card

- 时长：0.8–1.5 秒。
- 职责：建立心理目录和节奏停顿。
- 画面：白底、大号蓝色章标题，可加一个极小图标。
- 动作：快速淡入/上移，短暂停留后切出。
- 禁止：长句、解释、CTA。

### code-screen

- 时长：6–15 秒。
- 职责：证明命令、代码、错误、计划或测试真实发生。
- 画面：真实终端/编辑器；只高亮一个区域。
- 动作：局部推近、光框、红箭头、光标、滚动。
- 禁止：伪造代码、整屏小字、一次高亮多个主张。

### browser-demo

- 时长：6–15 秒。
- 职责：证明产品或网页行为。
- 画面：真实页面录屏，必要时裁掉无关栏。
- 动作：鼠标路径、点击、结果状态变化。
- 禁止：无法复现的模拟结果冒充真实产品。

### data-chart

- 时长：4–9 秒。
- 职责：排行榜、基准、性能、差异。
- 画面：最多 3–5 个关键值，强调主比较。
- 动作：柱增长、数值计数、标记锁定。
- 禁止：把完整表格缩小塞入一帧。

### character-beat

- 时长：3–8 秒。
- 职责：提出问题、操作、选择、惊讶、休息、验收或评价。
- 画面：峰峰与一个知识对象发生交互；若动作需要接触，人物和对象优先整帧生成。
- 动作：指向、投入、握柄、按压、连接、搬运、记录、回头、停顿。
- 交互规则：按 `interaction_mode` 填完整契约；推拉看位移与受力，握转看包裹与旋转，书写看笔尖与痕迹，坐靠看支撑与重心，行走看脚地接触与步态，递接看物件归属变化。
- 禁止：常驻角落、站桩比赞、只有嘴巴动、身体在目标附近却无有效关系、人物PNG遮住动作对象或接触点。

### result-proof

- 时长：5–12 秒。
- 职责：功能、正确性、性能和优化前后证据。
- 画面：左主张、右结果，或上问题、下证据。
- 动作：测试通过、对齐、数字变化、红→绿。
- 禁止：只说“成功”而无可读结果。

### comparison

- 时长：4–8 秒。
- 职责：方案、模型、前后、开源/封闭对比。
- 画面：两侧各一个主物件，中间一个判定轴。
- 动作：条件逐项落下，最终结论强调。
- 禁止：偷换评价维度。

### summary

- 时长：5–10 秒。
- 职责：回收前文模块和最终判断。
- 画面：一张总架构图或一组已出现物件汇聚。
- 动作：模块沿路径接回中心，最后只留一句判断。
- 禁止：引入新概念。

## 组合规则

- 前 5–12 秒必须是 `hook`。
- 大于 90 秒的视频至少有 2 个 `chapter-card`。
- 技术实测视频必须至少包含 `code-screen`/`browser-demo`/`result-proof` 中的两类。
- 连续 3 场不得相同模板；连续 3 场不得都只是文字卡。
- 每 20–40 秒至少出现一次“解释画面 ↔ 证据画面”切换。
- 峰峰出现率目标 15–25%，并优先分布在 Hook、转折、选择、评价。

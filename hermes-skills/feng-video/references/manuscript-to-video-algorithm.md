# 文稿到同类型成片：可泛化生产算法

本文件把参考视频中可复用的“知识表达语法”变成文稿驱动流程。它不复制原作者角色、画面、Logo、水印、原句、音乐或逐镜构图。

## 1. 先做场景预算

运行：

```bash
python3 scripts/plan_manuscript.py source.md --duration <目标秒数> --out production-plan.json
```

未给目标时长时省略 `--duration`。默认以 320 有效字符/分钟估算自然时长。

输出必须约束：

- Hook 截止时间；
- 总场景数和目标中位场长；
- 白底解释动画与真实证据画面的比例；
- 峰峰人物场景数；
- 章节卡数量；
- 需要真实证据支持的句子；
- 适合峰峰承担反应/选择的转折句。

完成标准：`production-plan.json` 存在，技术型文稿有 evidence scene 配额；若文稿没有证据线索，必须先建立采集清单，不能伪造。

## 2. 把文稿改写成五层因果链

无论题材长短，至少保留：

1. **Hook**：反常识结论、冲突或异常现象；
2. **Explain**：用一个日常物件解释一个抽象概念；
3. **Process / Mechanism**：展示过程、机制或实施路径；
4. **Proof**：功能、正确性、性能或可见结果；
5. **Judgment**：价值判断、边界和结论。

长技术视频在中间扩展为：挑战价值 → 概念教学 → 需求分析 → Spec/Plan → 开发转折 → 证据阶梯 → 总结。

完成标准：删除任一层都会破坏因果链，而不只是减少同义句。

## 3. 使用“视觉谓词”而不是给句子配插图

每个语义块先提取一个可见谓词：

- 输入、拆分、连接、筛选、写入、比较、报错、修复、增长、验证、汇聚；
- 再选择主物件、起始状态、动作、对象响应和结果状态；
- 最后选择 `visual_template`。

一个镜头必须能写成：

`主物件 + 动词 + 状态变化 + 结果`

例：不是“讲 Spec”，而是“模糊需求进入机器，被拆成 Spec 与 Plan 两张可验收卡”。

完成标准：重要动词在画面中可见；静态文字卡不能冒充对象动作。

## 4. 证据阶梯

技术实测默认按可信度递进：

1. 可运行 / 可操作；
2. 功能覆盖多个场景；
3. 正确性对照；
4. 性能数据；
5. 暴露缺点；
6. 优化动作；
7. 优化后的改善结果。

每层证据都必须保存来源、时间段、裁切方式、脱敏状态和对应旁白。真实录屏一次只高亮一个主张；白底动画负责解释证据，不替代证据。

完成标准：每个 `code-screen`、`browser-demo`、`result-proof` 都能回答“它证明了哪句话”。

## 5. 峰峰替换不是换皮

峰峰人物只承担剧情谓词：提问、操作、观察、选择、反应、验收。人物外观唯一来源是 `feng-ip`。

选择规则：

- 无接触：观察、思考、指向、惊讶，可用透明人物叠加；
- 表面接触：点击、书写、翻页，简单时可分层，复杂时整帧生成；
- 强交互：推、拉、握、转、搬、坐、走、递接，默认整帧生成。

每次出现必须写 `interaction_contract`，并限制在约 15–25% 场景。移除人物后，剧情动作或情绪功能应明显缺失。

完成标准：人物与对象存在可见因果关系，不是角落贴纸；手、接触点、受力、遮挡、对象响应与结果可信。

## 6. 节奏分配

- 普通解释场：2.5–8 秒；
- 真实录屏/证据：6–15 秒；
- 章节卡：0.8–1.5 秒；
- 视觉语义段目标中位：4–7 秒；
- 同一对象内部每 1.5–4 秒至少一次状态变化；
- 连续三场不得重复模板、布局和入场方式；
- 每 20–40 秒至少一次“解释 ↔ 证据”切换。

声音必须先生成，再用真实 SRT 时间更新场景边界。不能按文字估算直接锁死最终时间线。

## 7. 15 秒最小验收片

15 秒默认四场：

1. 0.0–3.0：反常识 Hook；
2. 3.0–7.0：峰峰执行核心转化动作；
3. 7.0–11.5：机制/过程；
4. 11.5–15.0：三项证据或结论回收。

推荐口播 58–75 个有效字符，默认 `feng-yunxi`。短样片可用 illustrative/code/hybrid，不得伪装真实录屏或宣称未做的实测。仍需输出真实音频、字幕、450 帧、MP4、联系表和 ffprobe/validator 报告。

短样片必须执行两级视觉QA：

1. **Hero Frame**：至少检查 Hook 完成态、人物动作中段、过程完成态、结尾完成态；人物接触失败时，先调整人物/对象位置和缩放，并同步修改 `interaction_contract`，不要直接全量渲染。
2. **时间联系表**：按 1–1.5 秒间隔检查黑帧、转场、字幕切换、任务逐项完成和结尾停留。转场采样可能出现主动白化，必须结合相邻帧判断，不能把单张浅色过渡误报为空帧。

供应商只返回一条覆盖整句的SRT时，保留原始SRT审计副本，再按语义拆显示字幕。最后一个结论字幕应占至少1秒；若不足，前移其起点并重渲染受影响帧。反向ASR只用于发现丢句、截断或错音轨，技术词和标点噪声不能替代人工字幕核对。

完成标准：15.000 秒、1920×1080、30fps、H.264、AAC 48kHz；峰峰至少出现一次并执行动作；结尾保留 ≥1 秒可读停留；Hero Frame和时间联系表均通过。

## 8. 原创性门禁

允许复用抽象语法：高密度旁白、白底信息动画、真实暗色证据、章节卡、对象级动作、人物剧情节点和证据阶梯。

禁止复用原视频的具体角色、机器人造型、芯片/宝箱等独特组合、原句、原镜头顺序、截图、Logo、水印、音乐和逐帧构图。每份文稿必须重新选择隐喻物件、动作链和证据来源。

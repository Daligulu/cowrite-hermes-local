# QA Checklist · 峰峰个人 IP 怪诞手绘

## 1. 输出规格

- 比例符合 Shot Config。
- 文件存在、非零，可由 Pillow 打开。
- 需要准确中文时，底图无模型文字；最终图文字与 `labels.json` 逐字一致。
- 无乱码、伪文字、多余空框、裁切或标签重叠。

## 2. 人物身份

对照本次使用的 1–2 张参考图和 `references/ip/feng/ip.md`：

- 年轻男性日系 2D 动漫比例，无眼镜。
- 浓密短深蓝黑发，自然侧分和发束，发梢不遮眼。
- 略长鹅蛋脸；自然清晰、略有眉峰的英气眉。
- 温和开放的深色眼睛，有瞳孔与小高光。
- 白 hoodie 的帽子与两根抽绳清楚。
- 深海军蓝夹克的翻领、前襟、口袋和少量褶皱存在。
- 不是泛化动漫男生、儿童 Q 版、真人照片、头像贴片或旧图拼贴。

任一核心锚点明显失败，人物一致性不通过。

## 3. 人物职责

- 峰峰亲自执行核心动作，不是角落站桩、主持人或装饰。
- 动作能改变、连接、分拣、检查或承接画面中的信息。
- 移除峰峰后，主要动作链会缺少执行者。
- 正文解释图人物通常占画面宽度 10–20%，不遮挡主路径和标签。
- 路径序列中默认只有一个峰峰，不在每个节点复制人物。

## 4. 内容与动线

三秒内应能：

- 点名 2–3 个具体物件；
- 说清每个主物件的问题源、动作入口、结果或状态职责；
- 沿箭头、路径、线缆、传送带或动作读完 A→B→C；
- 说出这张图唯一的核心判断。

失败信号：物件散落、泛化图标替代原文名词、箭头反向、步骤多于标题、异常分支被画成额外主节点。

## 5. 怪诞手绘风格

- 白色或极浅暖白背景，无纹理、渐变、阴影和深色大背景。
- 主体占 50–75%，连续留白不少于 25%。
- 场景是粗细不均、略抖动、可不封口的黑色手绘线稿。
- 人物保留完整个人 IP 配色；脸、耳朵、脖子和双手必须是自然暖桃肤色，白脸/灰脸/蓝色阴影脸直接判定失败。
- 深海军蓝仅用于峰峰头发和夹克；机器、纸张、卡片保持白底黑线，不得出现蓝色角阴影、蓝色排线或蓝色面板。
- 场景浅粉蓝面积建议不超过整图 2–3%，且不得与人物夹克连成连续蓝带。
- 保留 1–2 处软橙和人物暖肤色用于冷暖平衡。
- 默认 16:9 正文图运行 `scripts/check_color_balance.py --strict`；蓝色总量 >8%、深蓝 >7.8%、暖肤色/橙色 <0.5% 或蓝暖比 >10 时触发人工复核/重生成。
- 不像 PPT、正式流程图、课程课件、商业海报、科技 UI 或儿童插画。

## 6. 禁止元素

除非用户当前任务明确要求，不得出现：

- 狗、宠物、黄蓝运动服、球队/队徽、篮球；
- 黑色小黑豆、马帽女孩、Gimi 角色；
- 科技网格、电路、六边形、霓虹、赛博背景；
- 眼镜、胡须、帽子、耳机或素材里没有的配饰；
- 原参考图背景、矩形贴片边缘、九宫格/contact sheet 布局；
- 直接复制人物 PNG 到新画面。

## 7. 中文标签

- 生产图默认由 `scripts/add_labels.py` 本地叠加。
- 每张通常 2–5 个标签，每个 2–6 个简体中文字符。
- 标签优先放在物件、箭头、机器外侧或画面边缘空白区。
- 不遮挡脸、眼睛、眉毛、头发主体、hoodie 上半部、动作手臂或关键物件。
- 风格默认黑色无底短标签；用户要求信息卡时才使用圆角框。

## 8. 迭代顺序

1. 人物不像：增加第二张身份参考；把身份块放到 Prompt 最前并逐项重复锚点。
2. 人物只是装饰：重写 Shot Config 的站位、动作和信息职责。
3. 太像参考图：强调只借身份/动作，生成新背景、新装置和新构图。
4. 太 PPT：删标题、边框、整齐网格和多余箭头，改成一个怪诞场景。
5. 太复杂：删节点，只保留一个核心动作和 2–5 个物件。
6. 中文错误：不要继续赌模型写字；重生成无字底图并本地叠字。
7. Nano Banana 2 仍漂移：使用 Nano Banana Pro 做最终定稿。

最多重试 2 次。仍不过时，报告具体偏差，不得用原 PNG 覆盖来伪装修复。

## 交付判断

合格图应先让人觉得“有点怪”，再在一秒内看懂核心关系；人物像峰峰且确实推动故事；三秒内能点名具体物件并说清动线；中文准确。

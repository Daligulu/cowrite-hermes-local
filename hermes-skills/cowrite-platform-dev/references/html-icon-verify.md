# HTML 产物图标与样式校验（headless 视角）

> 本文补充 cowrite-platform-dev「验收工作流」中与 HTML 产物（公众号/微信组件、样式化产物）相关、但单靠 CDP DOM 断言看不出来的坑。gzh-design 排版产物类的检查也适用。

## emoji vs Unicode 几何符号（2026-08-26 实测）

**现象**：用 gzh-design 生成文末感谢卡，图标用 emoji（👍/👀/🔗）放在灰白圆底方框里，`headless chrome --screenshot` 渲染后**方框是空的**（图标不显示），只有转发那个因为带了主题色背景框、勉强能看到框但符号也空白。

**排查**：`fc-list | grep -i emoji` → 无匹配 → **环境没有 emoji 字体**（Noto Color Emoji 未装）。这不是产物缺陷，是字体缺失。

**结论（做成产物规则，不是环境抱怨）**：
- 做任何 HTML 产物里的**图标/交互符号**，优先用 **Unicode 几何符号**（♥ / ◎ / ↗ / ✓ / ★），跨端显示稳定。
- emoji 在无 emoji 字体的 headless / 服务器 / 部分定制 WebView 会渲染成空方框；即便某端能显示，为跨端一致仍应换 Unicode 符号。
- 验收时若截图里图标空白，**先 `fc-list | grep -i emoji` 确认是不是环境缺字体**，别误判成排版坏了、也别误判成「产物有 bug」而反复返工。

## 新增「适配多主题的组件」工作流（用户偏好）

用户偏好：参照一个样式做组件时，**先出一个样张 → 用户确认 → 确认后再融入版式（进组件库）**。不要做完了直接并入组件库再给用户看。

做法：
1. **参数化配色**：把组件每个颜色字段抽成主题变量（卡片浅底 / 描边 / 标题正文色 / 强调色 / 辅助色），以便一套组件套到全部主题。
2. **先做 1 个主用主题的样张**（如石墨极简），`validate_gzh_html.py` 校验到「完全合规」，再 390px headless 渲染截图给用户确认。
3. 用户确认后才写入组件库、登记 theme-index，成为常驻组件。

案例：文末感谢卡（作者签名 + 圆角卡：居中「点赞在看转发三连」标题 + 三个图标 + THANKS FOR READING）。石墨极简模板见 `gzh-design` 下方（用户自有 skill，需用户确认后入库）。

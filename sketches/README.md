# Cowrite 界面结构与交互优化方案（v0.1 待确认）

> 日期：2026-08-03 · 状态：**策划稿，待用户确认后实施**

---

## 一、现状问题（均来自实际试用）

| # | 问题 | 实测证据 |
|---|------|---------|
| 1 | **双入口重复**：顶栏 5 个按钮（配图/排版/Slide/Cowrite/发送）与下方「Hermes 内容生产」9 个动作功能重叠 | 用户不知道点哪一套；两个入口都提交同类型任务 |
| 2 | **命名不直观**：`Slide`、`Cowrite`、`发送` 语义模糊 | 不知道 Slide 是 PPT、Cowrite 是续写、发送到哪 |
| 3 | **反馈弱**：提交后仅页面顶部一排小字标签 | 看不到排队详情、无法点开追踪；任务中心入口藏在侧边栏深处 |
| 4 | **无引导**：欢迎页像 README 说明文字，不是可操作入口 | 新用户「不知道怎么用」 |
| 5 | **移动端桌面优先**：顶栏按钮挤压、任务面板在正文上方占位 | 390px 下已修溢出，但结构仍是桌面思路 |

## 二、设计目标

1. **单一入口**：所有「让 Hermes 干活」的操作只从一处发起，消灭双入口
2. **任务可见**：提交后进度立即可见、可展开管理
3. **移动优先**：拇指可达，主操作固定在底部，不用记功能藏在哪里
4. **可引导**：空状态/欢迎页变成「第一步做什么」的引导

## 三、目标信息架构

```
① 工作台首页（新增，替代欢迎页）
   ├── 最近页面（点击进入编辑）
   ├── 快捷开始：从想法创作 / 导入文章 / 打开项目
   └── 最近任务状态（点击进任务中心）

② 页面编辑器（重构）
   ├── 顶部：返回 ☰ · 标题 · 保存状态（只读，不再放操作按钮）
   ├── 正文区：Vditor（不变）
   ├── 命令栏（新，唯一操作入口）
   │     「告诉 Hermes 你想怎么处理这篇内容…」 + 常用 chips
   │     润色 · 配图 · PPT · 排版 · 发飞书 · 更多…
   └── 底部（移动端固定）：任务条 + 提交按钮

③ 任务中心（保留现有能力）
   ├── 状态筛选 / 详情 / 取消 / 重试 / 优先级（已有）
   └── 从页面底部任务条直接展开，不必先回侧边栏
```

## 四、关键交互设计

### 4.1 命令栏取代顶栏 5 按钮
- 输入自然语言：`把第二段改得更口语化`、`给全文配 3 张图`
- 或点常用 chips 快速发起：润色 / 配图 / 做 PPT / 公众号排版 / 发飞书
- 语义化动作名称，取消 `Slide`、`Cowrite` 这类自造词

### 4.2 提交后即时反馈
- 提交 → 底部任务条出现：`排队中 → 执行中（转圈）→ 已完成 ✓ / 失败 ⚠`
- 点任务条 → 展开任务中心对应任务（可取消、重试、改优先级）

### 4.3 移动端布局
- 底部固定操作区：命令输入框 + 提交（拇指可达）
- 底部 Tab 导航：`页面 / 任务 / 项目`（可选，减少侧边栏依赖）
- 弹窗保持 85vh 可滚动、动作单列（已完成）

### 4.4 空状态引导
- 无页面时：三张引导卡（从想法开始 / 导入文章 / 打开项目）
- 有页面无任务时：命令栏 placeholder 示例

## 五、实施分期（确认后执行）

| 阶段 | 内容 | 影响 |
|------|------|------|
| P1 | 移除顶栏 5 按钮；新增命令栏 + chips；底部任务条 | 消灭双入口，反馈可见 |
| P2 | 移动端底部 Tab / 固定操作区；任务条点开任务中心 | 移动优先 |
| P3 | 工作台首页（替代欢迎页）；空状态引导 | 新用户可上手 |
| P4 | 删除遗留按钮引用、清理任务记录、回归测试 | 收尾 |

## 六、草图

两份可交互草图（HTML，移动端优先），见同目录：
- `sketches/001-action-first/index.html` — 方案 A：行动优先
- `sketches/002-minimal-pocket/index.html` — 方案 B：极简收纳

**我的推荐：方案 A（行动优先）**——命令栏 + 底部任务条直接解决「双入口」和「反馈弱」两个核心问题，结构变化小、风险低；方案 B 视觉更干净但悬浮按钮发现性弱，新手需要学习。
